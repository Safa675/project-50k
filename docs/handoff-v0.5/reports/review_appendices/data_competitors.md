# Data, source claims and competitor audit

Audit date: 2026-10-02. Baseline: `received/Project_50K_Work_Handoff_v1/baseline/Project_50K_v0.3`. No baseline or working-copy files were modified. Public primary documentation was retrieved through web search/open; no accounts, credentials, paid feeds, trades, outreach, deployed API calls or rights approvals were obtained. Current page retrieval is documentation review, not a service test. Exact local reading coverage is in `data_competitors_coverage.json`; source check rows are in `data_competitors_sources.json`.

## Assessment

The main fund-incident statistics, fund-history placeholder correction, IEX coverage distinction, Solana top-account limit, and competitor-alert overlap are supported. The package appropriately avoids loss/fraud/prediction claims. The largest concrete provider hazards are inherited behavior in the inspected TEFAS wrapper: disabled certificate verification and substituting the local current date for a malformed allocation date. These need explicit admission gates before any adapter is implemented. The competitor desk review can now be materially strengthened with accessible official evidence for Fintables and the specialist/substitute products.

This is a specification audit. An absent real integration is a disclosed readiness gap, not evidence that a deployed product is malfunctioning.

## Checks that passed at documentation depth

- SPK's 23 September 2026 statement says the 17 September decisions cover 131 funds of seven portfolio-management companies and MKK records show 455,758 unique investors. The restriction against interpreting this as loss, fraud prevalence, or predictive validation is sound (docs/02:14; S02; turn3view0).
- SPK's 18 September statement attributes the low-free-float share observations to the regulator and dates the preparation process. The proposed product may use this as problem context, not as proof it could have prevented events (S03; turn3view1).
- The source-specific NaN/zero placeholders are corroborated in S06. FR-033/034 and docs/10:28 correctly prohibit historical AUM/investor inference from this path. Current wrapper history is price-only; current detail snapshots remain a distinct capability.
- BIST's official FAQ covers non-display and derived data uses. README/code access cannot grant upstream rights. DR-006 and DEC-006 are sound policy requirements; no legal permission was established here (S01/S05; turn6view4, turn11view6).
- Alpaca Basic real-time IEX is a partial venue feed. The existing IEX/SIP distinction and separate catalog/active coverage are correct (S08; turn11view8).
- SEC documents unauthenticated submissions/XBRL APIs, absent CORS, publication-driven updates and nightly bulk files. Server-side cached access is appropriate, subject to fair-access rules (S09; turn23view3, turn23view4).
- Binance documents a kline closed flag and separate base/quote volumes. Ethereum documents safe/finalized block tags and removed logs on reorgs. Solana explicitly returns 20 largest token accounts for a mint. Existing finality/account guards are appropriate (S10–12; turn26view5, turn26view8, turn26view9, turn23view7).
- DEX Screener's current pair schema has nullable liquidity and price fields and a pair-created timestamp; it is not a documented observation-as-of timestamp or a complete historical reserve series. The no-single-snapshot-drain guard is correct. Capture retrieval time and avoid treating `pairCreatedAt` as sample time (S13; turn29view0).
- CoinGecko documents provider IDs, market-cap ordering and `last_updated`; a dated catalog snapshot remains distinct from full market/on-chain monitoring (S14; turn26view11, turn32view6). The S14 `/coins/markets` route does not alone supply the chain/contract identity required by docs/10:21 and DR-001. Add the official `/coins/{id}` or platform-enabled coin-list metadata route, preserve null for native coins, and verify chain/contract before joining market and on-chain evidence (https://docs.coingecko.com/reference/coins-id ; https://docs.coingecko.com/reference/coins-list ; turn41view0, turn41view1).
- TradingView watchlist alerts and Koyfin price/technical/valuation/news/filing alerts are verified official overlap. No-competitor or first-alert-app claims would be unsupported (S30/31; turn12view0, turn23view10).

## Data-mode and readiness conclusion

All real providers retain LIVE_TESTED=false and RIGHTS_APPROVED=false. The only documented runnable evidence in the package is offline/synthetic reference behavior; this audit did not rerun that harness because another audit workstream covers execution. No candidate can be released solely because its public page, wrapper source, schema or SDK was accessible. The immediate data work is a field-level rights/capability inventory, transport/date-safe isolated adapter, and dated authorized samples, followed by semantic/failure validation. Synthetic or permission-cleared replay remains an explicitly labeled demo option; historical availability unknown cannot support causal detection claims.

Source retrieval failures: SPK help page produced zero readable lines (schema still unrecovered); a guessed BtcTurk OHLC URL returned tool internal error and was not treated as evidence; official public-endpoint index and rate page were successfully read instead. No direct TEFAS commercial-use permission was recovered by official-domain searches. The current S06 reported blob SHA was not independently confirmed. Sources outside assigned S01–14/S23/S30–32 were read locally as register content but their current scientific/framework/security accuracy was left to the other audit workstreams.
