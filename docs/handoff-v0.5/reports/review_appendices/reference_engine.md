## Interface/semantics changes for root's documentary corrections

- Evidence display rounding is decimal ROUND_HALF_UP at the integer boundary, with exact component decimal bounds. Do not use Python built-in round for this invariant.
- Offline Decimal arithmetic uses precision50 and ROUND_HALF_EVEN. This is reproducibility precision, not settlement/currency rounding. Monetary output scales still need asset/currency policy at implementation.
- `parse_timestamp` rejects more than six fractional digits rather than silently truncating them. Known zero offsets Z/+00:00 are accepted; RFC 3339 -00:00 means unknown offset and is rejected. Leap seconds and precision beyond microseconds are not supported by this helper.
- `eligible_evidence` filters supplied `published_at`, `observed_at`, `effective_at` and required `available_at`. It is not a complete JSON-schema validator, revision selector, rights checker or frozen replay builder; it returns input mappings, not immutable deep copies. Future scheduled-action interpretation needs event-type policy rather than a claim that this helper publishes announcements.
- `email_eligible` positive calls now require `dry_run=False` and verified nonempty `evidence_origins` containing only LIVE/DELAYED. Exact booleans are required throughout. Evidence truth, rights, status, admin identity, recipient state, durable caps and outbox state remain caller responsibilities.
- Delivery channels: EMAIL, IN_APP. Origins: LIVE, DELAYED, HISTORICAL_REPLAY, SYNTHETIC. Delivery classes: PERSONAL, GLOBAL_CRITICAL, DIGEST, UPDATE, CORRECTION. Only UPDATE/CORRECTION accept material_update_id. Hash key generation is not provider idempotency or durable delivery enforcement.
- Approximate percentage totals retain 0.1pp input tolerance, but any result beyond [0,1] is rejected. No missing/signed exposures are renormalized.

## Additional documentary/configuration findings forwarded to root

1. Detection weights exist both in `config/detection_defaults.json` and hardcoded evidence-strength-v1 logic. A validator checking one fixture score85 cannot detect all method/config discrepancies. Validate canonical v1 weights/version and boundary arithmetic, or explicitly version any future weight change. No evidence supports probability/calibration claims.
2. `config/admin_settings.json` uses `chat_daily_turn_limit`, whereas notification defaults use `chat_turns_per_user_daily`. A canonical name or explicit mapping is needed before admin settings are wired. Current offline code does not apply admin configuration.
3. Source revision lineage/selection is not represented by this helper. `source_version` alone does not identify document-series membership or prove when that version became known. Full TC-TIME-002 requires immutable historical versions, per-version availability and selection policy. Added regression checks only reject a future revision by its supplied availability and explicitly show that two eligible versions are both returned.
4. Boolean `same_feed` and `adjustment_verified` flags are caller assertions, not provenance validation. Tests establish guard handling, not IEX/SIP identity, corporate-action provider validation or prior-only baseline assembly.
5. Existing email tests only exercise a decision predicate/key. They do not satisfy full TC-NOT-001 durable one-alert/provider idempotency or TC-NOT-004 crash/reconcile behavior. Full TC-AI-001/006 are not run: adversarial JSON still truthfully says NOT_RUN_AGAINST_LLM.
6. All fixture data remains synthetic. Compatibility placeholder normalization is only for the documented borsapy price-history path; no arbitrary provider fallback is added.
