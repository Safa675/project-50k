# Contracts, AI boundaries, authentication and release audit

Audit date: 2026-10-02. Received baseline: `received/Project_50K_Work_Handoff_v1/baseline/Project_50K_v0.3`.

This is a specification/contract audit. The package has no implemented Next.js/FastAPI application, migrations, RLS deployment, provider adapter, production AI runtime or email sender. None of the findings below establishes an exploitable deployed vulnerability. Severity refers to the consequence if the incomplete contract is implemented literally. The received baseline was not edited.

## Existing controls that should remain

The package correctly specifies verified user-token RLS access for normal private operations, UUID admin membership rather than writable profile roles, private chats excluded from admin metrics, read-only bounded model tools, prompt-injection/source separation, public/private response separation, no replay web research or external sends, unsubscribe/send-time consent, durable idempotency, disabled/dry-run email and explicit rights/privacy gates. Its templates are blank records rather than invented approval. `.env.example` contains no real credentials. Those are requirements, not passed implementation tests.

The broader safe defaults are provisional engineering interpretations and do not remove mandatory email, global critical awareness, AI-native investigation, BIST or funds. None of this review justifies reopening confirmed product choices.

## Semantic validation and security gates, not new vulnerability claims

Static schema acceptance is deliberately narrower than claim truth or network security. CS-P04 (factual prose with omitted claims), CS-P05 (dangling evidence UUID), CS-P07 (`javascript:` locator), CS-P08 (incoherent tool usage) and CS-P09 (reversed timestamps) all pass the shipped schema. They demonstrate why existing documented server semantic/output/rendering gates are required; they do not prove a running application bypass. JSON Schema cannot compare arbitrary dates, resolve membership of IDs in sibling collections or verify sentence support on its own.

Before enabling AI output: enforce evidence/claim/calculation reference existence and uniqueness, canonical asset/context equality, right/time/revision eligibility, deterministic arithmetic and support for all material prose. A reviewer model is supplemental. No raw HTML or unvalidated locator becomes a clickable URL. Typed server-side context and validation must run even when a prompt is adversarial.

Before a custom fetcher: implement and test the already-required strict public resolver, including redirects, IPv4/IPv6 private/reserved/metadata destinations, DNS changes, URL credentials and response byte limits. No fetcher exists here, so SSRF/DNS-rebinding protections are unverified rather than confirmed broken.

Before personal endpoints: verify two-user isolation and child message ownership, private cache behavior, safe errors, revoked membership/session behavior and deletion suppression. Before mail: verify exact-revision approval, consent/category withdrawal, dedup/retry races, origin prohibition, caps/kill switches and provider reconciliation. Empty/invalid `LLM_DAILY_BUDGET_USD` must fail closed for paid calls rather than imply unlimited spend; add this environment interpretation before runtime implementation.

- CS-AUTH-01: [Supabase — Signing out](https://supabase.com/docs/guides/auth/signout), inspected 2026-10-02, especially lines 146–148 of retrieved page. Already-issued access JWTs remain valid to expiry after session signout. Browser reference: `turn39view1`.
- CS-AUTH-02: [Supabase — User sessions](https://supabase.com/docs/guides/auth/sessions), inspected 2026-10-02, especially lines 108–110 and 172–176. A `session_id` maps to the stored session; sensitive actions can check continued session presence. Browser reference: `turn39view0`.
- CS-AUTH-03: [Supabase — Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous), inspected 2026-10-02, especially lines 88–101 and 188–206. Anonymous Auth sessions use the authenticated role and are distinguished by `is_anonymous`. Browser reference: `turn39view2`.
- CS-AUTH-04: [Supabase — JWT Signing Keys](https://supabase.com/docs/guides/auth/signing-keys), inspected 2026-10-02. Official distinction between asymmetric signing keys and legacy/shared-secret configurations; use current provisioned project's settings, not an assumed existing account. Browser reference: `turn39view3`.

These source facts support specification clarification; they do not validate a provisioned Project 50K Auth instance. Root integration should reopen cited pages before including their browser refs in a user-facing answer.

## Remaining material decisions

No new product preference is needed to correct missing paths, mismatched enums, calculation provenance or immutable replay/release metadata. Exact admin membership, domains/controller, retention basis, budget, provider rights/accounts and external-send authorization remain external build/release prerequisites. Public versus restricted demonstration and accepted reduced live coverage remain owner decisions. A desired instant-revocation policy versus expiry-bounded ordinary access is an engineering trade-off that can be delegated; sensitive admin release must not depend solely on a previously valid token.
